Connection model

Your Mac remains the workspace.

Projects and developer tools stay where they already run. Captured media and remote input travel over end-to-end encrypted WebRTC between linked devices.

Hosted services still process the account, routing, device, request, and network metadata needed to operate the connection.

Questions, answered plainly

Before you open the tunnel.

Does my project move to the cloud?

No. Your project and coding tools continue running on your Mac. The phone receives the media and control data needed for the remote session over encrypted WebRTC.

What can the hosted service see?

The hosted control plane processes account, device, routing, request, and network metadata. It does not receive plaintext WebRTC media or DataChannel content.

Which coding agents are supported?

Mac Screen and scoped Terminal are Supported. Codex, Cursor, Gemini CLI, and OpenCode integrations are available as Preview paths. Claude Code and generic mirroring are Experimental.

Does my Mac need to stay awake?

Yes. Glasstunnel includes an optional Keep Mac Awake setting for remote availability, but the Mac must remain powered on and connected.

Do I need an iPhone app?

No. The phone experience is an installable web app that runs in Safari or Chrome at app.glasstunnel.io.

Can I self-host it?

Yes. The repository includes self-hosting documentation for the signaling and TURN path, plus local development infrastructure.

Why are macOS permissions required?

Screen Recording lets Glasstunnel capture the screen or selected window. Accessibility allows approved remote prompts, text, and clicks to reach local coding apps.

How do updates work?

Glasstunnel does not silently update itself. Download a newer release from GitHub or run brew update followed by brew upgrade --cask datawithfurkan/glasstunnel/glasstunnel.
